## 1. 测试手段分级（定义）

| 级别 | 名称 | 手段 | 适用 |
| --- | --- | --- | --- |
| L1 | 代码级 | `tsc --noEmit` / `vue-tsc` / `pnpm build` / 单测(jest/vitest) | 所有阶段必跑 |
| L2 | 接口级（后端） | curl/HTTP 断言：状态码 + 业务错误码 + 数据结构，**必须含权限拒绝路径**（2001/2003/2004/3006） | 后端阶段必跑 |
| L3 | 业务链路（后端） | 跨模块状态机链路逐点断言（对照 docs/02 状态机与 docs/03 §9 E1-E16） | 涉及流转/联动的阶段 |
| L4 | 端到端（前端） | **真实浏览器自动化**（ego-browser 优先）走用户操作路径：输入→点击→断言可见结果与存储状态 | 前端阶段必跑 |
| L5 | 人工验收 | 用户在浏览器实际操作确认 | 最终确认；**不能替代 L4 留痕，但可作补充结论** |

**通过标准**：该阶段「测试矩阵」全部用例结论 = PASS；存在 FAIL 必须修复后重跑；无法修复的 FAIL 项，交付说明中显式列为「不通过项+影响+顺延计划」，**禁止静默跳过**。

## 4. 台账维护规则

1. 本文档 §3 是**唯一状态台账**：每阶段结束时由实现者更新，状态只允许 `未开始/进行中/通过/不通过`；
2. `通过` 的前提 = 该阶段矩阵全 PASS（或 FAIL 项已修复回归 PASS）；
3. `未验证` 项必须在交付说明顶部置顶声明；
4. 测试用例命令/脚本可复现：后端 curl 存 `apps/server/test/http/`（.http 或 .sh），前端 ego 脚本存 `apps/web/e2e/ego/`（F2 起）。
