## 1. AI 协作纪律：不明确即停【强制】

> 来自 kb《工程流程规范》，人与 AI 通用。模型与人天然倾向"填充空白让程序能跑"，停下来问必须靠纪律强制。

- **未确认即禁止决定**：契约（字段语义/类型/口径）、数据形态、业务规则未确认前，禁止自行选择默认行为——不得静默兜底、不得编造占位数据、不得用生成值覆写存量数据。
- **处理方式二选一**：① `// TODO(待确认): <问题>` 显式标记 + 保守路径（不改变现有行为）；② 停下来向用户/产品抛出问题。
- **兜底必须显式**：降级/默认分支必须三选一——message 提示、日志上报、UI 阻断；禁止静默吞掉不确定性。
- **高危兜底黑名单（遇到即停）**：
  - catch 后把无 code 的异常体判为成功（`res.code === undefined` 落 `ok: true`）；
  - 缺参/缺 id 时落入更大范围的操作（单条审批缺 id 静默执行全量）；
  - `res.data?.[0]` 取首条猜记录（"预期单条"必须显式异常化）；
  - 按中文字符串猜字典语义做业务联动；
  - 字段缺失时编造合理-looking 的展示值。
- **修复纪律**：涉及字段语义/接口契约的缺陷，修复前以 **Swagger 响应体为唯一事实源**闭环确认；确认不了宁可保守标注，禁止按猜测改逻辑。
- 本项目补充：**状态流转合法性以 docs/02-业务流程规格 为唯一事实源**（禅道源码 file:line 证据），编码时禁止凭印象写流转条件。

## 2. Git 提交规范【强制】

### 2.1 Husky 强制检查

提交必须通过钩子，**禁止绕过**（`--no-verify` 仅紧急修复可用，事后必须补修并在提交描述中注明）。

| 钩子 | 检查 | 通过标准 |
| --- | --- | --- |
| pre-commit | `lint-staged`：暂存文件 prettier --write | 全部通过 |
| pre-commit | `turbo lint`（P0/F0 接入各包 eslint 后启用） | 0 errors |
| pre-commit | `turbo test --affected`（P1 起接入核心单测后启用） | 通过 |
| commit-msg | commitlint（`commitlint.config.js`） | type 合法、subject 非空 |

### 2.2 提交信息格式

`type: 中文描述`，type 使用英文枚举，描述使用中文：

```
feat: 新增需求 stage 自动计算引擎
fix: 修复任务 finish 时 consumed 重复累加
docs: 更新 03-接口与契约 shared 映射表
refactor: 提取 useBoard 乐观更新回滚逻辑
chore: 初始化 monorepo 骨架
```

type 枚举：`feat fix docs style refactor perf test build ci chore revert`。

### 2.3 禁止行为

| 禁止 | 说明 |
| --- | --- |
| `git commit --no-verify` | 绕过 husky（紧急例外见上） |
| 提交含 `console.log` / `console.debug` | 调试代码不入库；错误日志用 `logger.error`（后端）/`console.error`（前端） |
| 提交含注释掉的大段代码 | 删除或提 issue 跟踪 |
| 提交含无注释的 `as any` | 类型断言必须有局部说明（§4.2） |
| 提交含未使用变量/死代码 | eslint `no-unused-vars` 必须清理 |
| 提交密钥/内网地址/真实密码 | 安全规范见 §9 |

## 3. 命名规范【强制】

### 3.1 文件与目录

| 类型 | 规则 | 示例 |
| --- | --- | --- |
| 目录（views/components 业务域） | kebab-case（Vue 业务目录）或模块名 | `views/execution/`、`components/business/action-toolbar/` |
| Vue 单文件组件 | PascalCase；业务组件独立目录 + `index.vue` | `ActionToolbar/index.vue` |
| TypeScript 文件 | camelCase | `useBoard.ts`、`status-tag.ts` |
| Composables | camelCase，`use` 开头，文件名=函数名 | `useBoard.ts` → `useBoard()` |
| 后端 Nest 文件 | `xxx.controller.ts / xxx.service.ts / xxx.repository.ts / xxx.dto.ts`，kebab-case | `task.service.ts` |
| shared 契约包 | kebab-case，与 docs/03 §12 文件清单一致 | `socket-contract.ts` |

### 3.2 类型命名（前端，与后端 DTO/VO 对齐）

| 类型 | 规则 | 示例 |
| --- | --- | --- |
| 请求参数（对齐后端 DTO） | `<Resource>QueryDto` / `<Resource>SaveDto` | `StoryQueryDto`、`TaskSaveDto` |
| 响应实体（对齐后端 VO） | `<Resource>Vo` | `StoryVo`、`TaskDetailVo` |
| 列表行 / UI 项 | `<Resource>Item` | `TaskBoardItem` |
| 枚举/常量对象 | `<Entity><Property>` 或直接状态描述 | `StoryStatus`、`TaskStatus` |
| **一律 import @zentao/shared** | API 契约类型禁止本地重复定义 | 见 docs/03 §12 |

### 3.3 API 函数命名（前端 api/ 层）

| 操作 | 命名 | 示例 |
| --- | --- | --- |
| 查询列表 | `getXxxList` / `getXxxPage` | `getStoryList` |
| 查询单个 | `getXxx` | `getTaskDetail` |
| 新增 | `addXxx` | `addBug` |
| 修改 | `updateXxx` | `updateUser` |
| 兼具新增/编辑 | `saveXxx` | `saveExecutionConfig` |
| 删除 | `deleteXxx` | `deletePlan` |
| 导出/导入/模板 | `exportXxxList` / `importXxxData` / `downloadImportTemplate` | |
| 其他动作 | 动词+名词（对齐后端动词端点） | `startTask`、`resolveBug`、`closeStory` |

**旧世代命名禁令**：`queryXxx/pageXxx/listXxx/detailXxx/createXxx/removeXxx/saveOrUpdateXxx` 一律禁止，评审按缺陷处理。

### 3.4 后端命名

- 类：`TaskService / TaskRepository / TaskController / CreateTaskDto / TaskVo`；
- 状态流转方法与禅道动作同名：`start/finish/pause/cancel/close/activate/resolve/confirm`（语义见 docs/02）；
- 错误抛出统一 `BusinessException(ErrorCodes.XXX)`，禁止裸 `throw new Error` 穿透到响应层。

## 4. TypeScript 规范【强制】

### 4.1 基础

- 全部包启用 `strict: true`，禁止隐式 `any`；
- 显式类型标注公开函数签名与 ref 泛型；泛型兜底用 `unknown` 不用 `any`；
- 可选链 `?.` + 默认值；可写计算属性优先于 watcher 回写。

### 4.2 `as any` / 类型断言规则

```ts
// ❌ 禁止：无理由断言
(props as any).onClose();

// ✅ 允许：局部注释说明原因
// shared 类型未覆盖 socket 扩展字段，暂时放宽
const payload = raw as unknown as CardMovePayload;

// ✅ 更好：扩展类型声明
declare module '@zentao/shared' { ... }
```

### 4.3 实战教训（kb 前端编码规范原样采纳，均为真实事故）

- `===` 比较前确认两侧类型一致——**ID 字段用 `String()` 归一化**（string vs number 恒不等，曾致超管保护静默失效）；
- 树/表格 key 与数据源字段必须同类型（严格相等匹配）；
- 类型不匹配时修数据/类型本身，禁止 `as unknown as` 强转掩盖根因；
- 校验不信任类型声明的理想形态：后端可能返回字符串 `"5"`，边界处 `Number()` 归一而非 `typeof` 断言；
- Promise 链必须有 catch 终止，禁止裸 `.then()`；
- `finally` 只做资源清理（loading 复位/清定时器），**禁止承载业务状态跃迁**；
- **Commit-after-Persist**：持久化成功才关弹窗/刷列表/改状态，失败保持现场供重试；
- 二态枚举判断用 `===`，不用单值 `includes`；
- 部署路径/URL 走环境变量（`import.meta.env.*` / `process.env`），不硬编码。

### 4.4 响应类型（本项目载体）

```ts
// packages/shared/dto/http.ts 单一定义，双端 import
interface ApiResponse<T> { code: number; message: string; data: T; traceId: string; timestamp: number }
interface PageResult<T> { list: T[]; total: number; page: number; pageSize: number }
```

- API 函数显式标注返回泛型：`getStoryList(params): Promise<PageResult<StoryVo>>`；
- 禁止在业务代码自造 `R / RList / TableDataInfo` 类临时响应包装。

## 5. 后端 NestJS 规范【强制】（本项目补充，kb 无对应）

### 5.1 分层与职责

| 层 | 职责 | 禁止 |
| --- | --- | --- |
| Controller | 路由/权限装饰器/Swagger 注解/DTO 接收 | **禁止写业务逻辑** |
| Service | 流转编排、校验、副作用调度（对应禅道 zen 层） | 禁止直接拼 SQL |
| Repository（TypeORM） | 数据读写与聚合（对应禅道 tao 层） | 禁止掺入流转判断 |
| Module | 装配与导出 | 循环依赖用 `forwardRef` 显式声明 |

- 状态流转三层对齐：入口 `isClickable` 校验（`isTransitionAllowed`）→ Service 表单级校验 → Repository 落库 + 副作用钩子（docs/02 §0 约定）。

### 5.2 DTO 与校验

- 所有入参走 `class-validator` DTO，`whitelist + forbidNonWhitelisted` 全局开启；
- 错误码从 `@zentao/shared/error-codes` import，**禁止魔法数字**；
- 分页/排序参数复用 `PageQueryDto`，上限 100 强制校验。

### 5.3 事务与副作用

- 跨表写操作（如任务完成→工时聚合→stage 重算→通知）用数据库事务包裹，副作用（action 日志/通知）在事务提交后异步派发（事件总线），**事务内不做网络调用**；
- 隐式状态迁移（记工时驱动任务状态）必须复用同一状态推导函数，禁止在多个 Service 重复实现。

### 5.4 测试纪律

- docs/04 §10 必测清单中的 Service 方法，改动时必须同步补/改单测（turbo test --affected 卡门禁）；
- 状态机测试用表驱动（合法迁移表 = docs/02 状态机逐行映射）。

## 6. 前端 Vue3 规范【强制】

### 6.1 组件结构与命名（kb Vue3 规范采纳）

- `<template>` → `<script setup lang="ts">` → `<style>`；script 内顺序：导入 → Props/Emits 接口 → defineProps/defineEmits → 响应式数据 → computed → 方法 → 生命周期；
- 组件文件 PascalCase；基础组件 `ui/`（shadcn-vue 生成），业务组件 `components/business/<name>/index.vue`；
- Props：interface + `withDefaults`；布尔 prop 用 `is/has/should` 前缀；Emits：interface 声明；
- **双向绑定优先 `defineModel`**（Vue 3.4+）；模板属性 >2 个换行；属性顺序：指令 → 绑定 → 普通属性。

### 6.2 Composables（kb 5.5 采纳）

- `use` 前缀、单一职责、返回值命名清晰（禁 `v/o/c`）；
- 副作用在 `onUnmounted` 清理；异步请求 in-flight 去重 + `onScopeDispose` 忽略卸载后结果；
- 不在 composable 内直接取 router/DOM，通过参数传入；
- 直接解构返回的 ref 会丢失响应式——保留对象或用 `toRefs`。

### 6.3 数据边界（kb §9 决策框架精简）

```
UI 专属临时状态（展开/loading/选中）→ 本地 ref
后端数据且仅本组件使用 → 组件内 vue-query 自治
跨兄弟共享 → 提升父组件 or Pinia
纯展示 → props；复用差异 → props 控制
```

- 服务端数据一律走 vue-query（key 约定见 05 §2）；精确失效而非全量 `invalidateQueries`；
- 禁止子组件 import 父组件私有 store；跨层级配置用 provide/inject（主题类）。

### 6.4 拆分决策（kb 3.2 精简）

弹窗内容 >50 行 → 独立组件；表格工具栏 → `XxxToolbar`；逻辑耦合的长模板先提 composable 再考虑拆组件；性能敏感路径不过度拆分。

### 6.5 样式（Tailwind 适配）

- 优先 Tailwind 原子类 + shadcn-vue 语义 token（`bg-background`/`text-muted-foreground`），禁硬编码色值；
- 复杂动效/第三方组件覆写才用 `<style scoped>`，深度选择器用 `:deep()`；
- class 排序由 `prettier-plugin-tailwindcss` 自动处理（F0 接入），禁止手工排序争执。

## 7. 复用优先与死代码【纪律】

- 动手实现前先检索既有资产（`components/business`、`composables`、`@zentao/shared`），禁止手写第三份等价物；
- 禁止引入与现有技术栈冲突的新依赖（加依赖须在 PR 描述说明理由）；
- 修改 shared 契约包公共 API 时必须同步双端并回填 docs/03 §12；
- 死代码：不可达分支、死变量、注释代码块一律删除；"有接口无入口"类清理需先与产品确认挂载意图。

## 9. 安全规范【强制】

- 禁止将密钥、服务器密码、内网地址、真实用户数据写入代码或文档；配置说明只写配置项名称与用途；
- `.env*` 已被 gitignore（模板 `.env.example` 除外）；疑似泄露立即轮换并上报；
- 依赖引入需走 PR 评审（供应链安全）；锁文件（pnpm-lock.yaml）必须提交。
