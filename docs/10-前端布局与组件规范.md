## 3. 状态标签与动作条（业务组件约定）

- **StatusTag**：`<StatusTag entity="story" :status="story.status" />`——颜色/文案映射集中 `src/types/status.ts`（枚举 import 自 @zentao/shared）
- **ActionToolbar**：动作按钮 = 权限点（v-permission）× isClickable 前置状态（shared TASK_TRANSITIONS 等表）双条件渲染；点击走 useConfirmAction 确认弹窗
- **列表页筛选**：状态页签（各实体 status 枚举）+ 关键字 + 下拉筛选；筛选状态入 URL query（可分享/刷新保持）

## 6. 禅道风格基线（2026-11-06 复盘，舒适度差距与收敛方案）

> 背景：F2/F3 交付后对照禅道 22.x 实机复盘——功能齐但"不如禅道舒服"。根因不在组件库，而在**信息层级、视觉噪音、交互出口**三类系统性差异。本节为风格基线，后续页面一律对齐。

### 6.1 禅道做对了什么（风格总结）

| 维度 | 禅道做法 | 我们此前的偏差 |
| --- | --- | --- |
| 导航分层 | 顶部主导航（换语境）+ 左侧暗色侧栏（换页面）+ 底部多页签 | 只有侧栏单层，页面间层级语境弱 |
| 视觉分区 | 冷灰底 + 白卡片分区，每卡有"标题行 + 更多>"，区块留白充分 | 卡片化不足，区块边界靠细线，呼吸感差 |
| 数字层级 | 统计 = 小标签在上 + **大号数字在下**，数字是主角 | 标签与数字平级，层级弱 |
| 状态呈现 | 列表里**圆点 + 文字**（激活红/解决绿/关闭灰），标签只出现在详情头等强调处 | 满屏 el-tag，彩色噪音大 |
| 行内操作 | 操作列 = **灰色文字链接**，hover 变主色；危险动作红色 | 一排彩色 link 按钮，扫读困难 |
| 上下文饱满 | 详情页 = 头部（面包屑+标题+状态+动作条）+ 左主栏（描述 + **操作记录时间线**）+ 右栏（基本属性 + 关联对象块，名称可点） | 无面包屑、无操作记录、右栏全是裸 ID 数字 |
| 跨实体引用 | 一律"标题 + ID"可点跳转，从不让用户记裸 ID | 属性面板显示裸数字 ID |
| 全局搜索 | 顶栏搜索框跨实体搜，结果分组下拉直达 | 无 |
| 行内指派 | 列表"指派给"单元格直接下拉改指派，不进详情 | 无 |
| 空态 | "暂无XX"必须带出口（新建按钮/引导文案），不留死胡同 | 只有"暂无"两个字 |
| 筛选记忆 | 筛选状态进 URL，可分享/刷新保持 | 全部在内存 |

### 6.2 交互边界（用户在每个界面能/不能做什么）

1. **两级到详情**：列表单击标题/ID 进详情；详情内关联对象可点跳转；不用弹窗承载详情。
2. **写操作三型**：纯动作（暂停/取消/关闭）轻确认；表单型动作（开始/完成/解决/激活）弹表单弹窗；破坏型（删除）红色确认——均由 useConfirmAction 收口。
3. **权限即不可见**：无权限按钮不渲染（不置灰），三层控制不变。
4. **反馈即时**：成功 toast + 精确失效刷新；失败 toast 服务端原因；无静默失败。
5. **后端没有的不做**：批量操作/自定义查询/导出（无端点）不出现 UI；case/测试单/执行无操作审计 → 详情不放假时间线。
