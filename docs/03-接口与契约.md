## 1. 全局约定（回顾）

- 前缀 `/api/v1`；全局 `JwtAuthGuard`，仅认证类端点标 `@Public()`。
- 统一响应体：`{ code, message, data, traceId, timestamp }`；分页：`page/pageSize`（默认 20 / 上限 100），响应含 `total`；排序：`sortBy/sortOrder`。
- **权限点命名 = `module.action`，与禅道 grouppriv 的 (module, method) 完全同构**——`@Permissions('story','create')` 双段装饰器直接映射 DB 行 `(module, method)`，未来迁移禅道权限数据可直导。
- 状态流转端点显式动词化（`/start /finish /close /resolve /activate`…），一个动词端点 = 一个权限点 = 一个禅道方法。

## 3. 权限点体系

### 3.1 种子生成方案（定案）

1. **单一事实源 = 控制器装饰器**：每个路由标 `@Permissions('story', 'create')` + Swagger 描述。
2. 启动/构建时执行 `permission:seed` 脚本：扫描全部路由元数据 → 与 `sys_permission` 幂等对齐（新增插入、缺失标记 deprecated）。
3. **CI 校验**：存在无权限点的路由（非 `@Public`）即构建失败——保证权限点无遗漏。
4. 预置角色：超级管理员（is_super 直通）/ 管理员 / 产品经理 / 项目经理 / 研发 / 测试 / **受限组 limited**（对齐禅道 limited 组：仅操作被指派对象）。预置角色×权限矩阵随种子脚本一并初始化。

### 3.2 数据权限（回顾设计文档 §9 + 流程细化 §2.2）

- 作用域：program / product / project / execution；acl ∈ open / private（+custom 预留）。
- 可见性集合预计算（Redis 替代 zt_userview），列表查询统一 `IN(可见集)` 过滤；`DataScopeGuard` 校验单对象访问；private 对象放行条件 = 白名单(sys_acl) ∪ 团队成员 ∪ 干系人 ∪ 管理员。
- **项目级权限覆盖**（对齐 zt_group.project / zt_usergroup.project 语义）：`sys_user_role` 增加 `project_id` 维度（0=全局），解析用户权限时项目级组优先于全局组。

## 4. 接口清单（按模块）

> 图例：权限点列 `story.create` 即 `@Permissions('story','create')`；「校验」列引用《流程细化》章节。批量端点统一 `POST /xxx/batch-<action>`。列表端点均支持筛选/分页/排序，不再逐条列。

| 端点 | 方法 | 权限点 | 说明 |
| --- | --- | --- | --- |
| /auth/login | POST | @Public | 登录，返回双 token；失败计数→锁定（2008） |

## 6. Socket.IO 事件契约（P1 补全）

- **连接**：namespace `/ws`；握手 auth: `{ token }` → 服务端 JWT 校验，失败断开。心跳 ping/pong 25s。
- **Room**：进入看板页 → `join execution:{id}`；离开/断开自动退出 + presence 广播。

**Client → Server（均带 ack 回调）**

| 事件 | Payload | 服务端行为 | ack |
| --- | --- | --- | --- |
| board:join | { executionId } | 加入 room，返回当前看板全量 | `{ ok, board }` |
| card:move | { executionId, taskId, fromColumnId, toColumnId, fromLaneId?, toLaneId?, ordinal } | ① 校验目标列合法（5203）② 按状态↔列映射执行对应任务动作（start/finish/pause/activate/cancel/close，可能失败 4701）③ moveCard ④ 广播 | 成功 `{ ok, task, column }`；失败 `{ ok:false, code, message }`（前端按 code 回滚） |
| card:reorder | { executionId, columnId, taskId, ordinal } | 仅排序，不改状态；写 cell.cards 顺序 | `{ ok }` |
| presence:heartbeat | { executionId } | 刷新在线集合 | 无（静默） |

**Server → Client（room 内广播，含 actor 信息用于冲突提示）**

| 事件 | Payload | 说明 |
| --- | --- | --- |
| presence:sync | { members: [{userId, account, realname}] } | 在线成员全量（join/leave 后重发） |
| card:moved | { taskId, fromColumnId, toColumnId, ordinal, actor } | 拖拽结果 |
| card:status:changed | { taskId, status, task(摘要), action, actor } | 任何任务状态变化（含非拖拽路径，如他人 finish） |
| card:updated / card:created / card:deleted | { taskId, ... } | 编辑/新建/删除任务 |
| column:updated / lane:updated | { columnId, limit, ... } | 列/泳道变更（WIP 变化即时生效提示） |
| board:wip:exceeded | { columnId, limit, current } | WIP 超限**警告**（不拦截，对齐禅道仅提示语义） |
| board:refresh | { reason, code? } | 服务端处理失败要求客户端全量刷新（回滚兜底） |

- 多实例：`@nestjs/websockets` + `socket.io-redis-adapter`；写库只发生在服务端事件处理内（唯一事实源），客户端乐观更新失败即回滚。
- 幂等：事件携带 `eventId(uuid)`，客户端去重。

## 7. 搜索与自定义查询（P1 补全）

- **列表过滤 DSL**（所有 GET 列表统一）：`?filters=field:op:value` 多段组合（op ∈ eq/neq/in/like/gt/lt/between），字段白名单由各模块声明（防注入）；复杂组合用 POST body + `POST /lists/query`。
- **自定义查询**（对齐禅道 queryID 机制）：`GET /queries?module=story`（我保存的查询）、`POST /queries {module, title, filters}`、`DELETE /queries/:id`——列表端点接受 `queryId` 直接套用。
- **全局搜索**：`GET /search?q=&types[]=story,task,bug...`，按可见集过滤，MySQL 全文索引 + LIKE 兜底；ES 为后续可选项（不在一期）。
- **导入导出**（对齐禅道 Excel 能力，范围一期限 story/case/bug/task）：
  - 模板：`GET /{resource}/export-template`（xlsx）；
  - 导入：`POST /{resource}/import`（multipart）→ 同步小批量(<500 行)/异步任务 + 行级校验报告（错误码 3009，返回行号+列名+原因）；
  - 导出：`GET /{resource}/export?filters=...`（当前筛选结果导出）。

## 8. 安全加固清单（补设计文档 §9）

| 项 | 方案 |
| --- | --- |
| 传输 | 全站 HTTPS；Swagger 仅 dev/staging 暴露（prod 环境变量关闭） |
| 认证 | bcrypt(cost 12)；登录失败 5 次锁 15 分钟（对齐 zt_user.fails/locked）；refresh token 轮换（旧 token 立即失效） |
| 会话 | token denylist（登出/改密全端失效）；改密后 access token 剩余寿命 ≤30min |
| 接口 | 全局 rate limit（登录 10 次/分钟/IP；写接口 60 次/分钟/用户，@nestjs/throttler） |
| 注入 | TypeORM 参数化（禁字符串拼接 SQL）；排序/筛选字段白名单 |
| XSS | 富文本字段（spec/verify/steps/desc/comment）入库前 sanitize-html 白名单清洗；导出文件转义公式注入（= 开头列前缀 `'`） |
| CSRF | 双 token 放 Header（非 Cookie）天然免疫；若后续支持 Cookie 模式补 CSRF token |
| 文件 | 扩展名+MIME 双白名单（对齐禅道 uploadType 配置）、大小上限、存储键 uuid 不可预测、下载走签名 URL、禁执行位 |
| 越权 | 单对象访问统一走 DataScopeGuard（禁止控制器内散落判断）；水平越权用例纳入 E2E |
| 审计 | 全部状态流转/删除/权限变更写 zt_action_log + history（§9.1 流程细化） |

## 10. CI/CD 与监控（补设计文档 §13）

- **CI**（GitLab CI / 任意流水线等价）：lint → test(单测+e2e，起 mysql/redis service 容器) → `permission:seed --check`（权限点漂移校验）→ build multi-stage 镜像 → 推送镜像仓库 → 部署（compose/编排在目标环境执行 migration + 启动）。
- **迁移策略**：生产 `migration:run` 先于应用启动（compose depends_on + 健康检查门禁）；回滚 = 镜像回退 + migration down（危险操作人工确认）。
- **监控**：`/api/v1/health`（DB/Redis）供探活；结构化 JSON 日志（traceId 贯穿）接入采集；关键指标暴露 Prometheus 格式（HTTP 时长/错误率、Socket 在线数、队列深度）；告警阈值：5xx 率>1%、P99>1s、Redis 内存>80%。

## 11. doc / oa 流程细节（补《流程细化》缺口）

- **doc**：空间(space: product/project/execution/personal)→库(lib)→文档；正文版本化（编辑生成新版本，可回看历史）；模板（createTemplate，源码核实有模板类型管理）；文档关联对象（uploadDocs 支持 objectType+objectID 挂载）。
- **todo**：状态 wait→doing→done→closed（activate 可回退）；type=task/bug/story/test 时 objectID 关联业务对象，**业务对象完成不自动完成 todo**（禅道语义：由用户 finish）；周期待办 cycle（createCycle）生成策略：一期可延后。
- **effort 日志**：除任务工时外支持独立填报（objectType=custom 场景走 oa 模块入口）；日报/周报按 account+date 聚合只读视图（对应禅道 my/work）。

## 12. packages/shared 契约同源包（monorepo，ADR D001）

前后端同仓后，本文件中所有「双端必须一致」的契约收敛为**零依赖纯 TS 包** `packages/shared`，由双端 import——本文档是该包的**规格来源**，编码时以下表为映射关系：

| shared 文件 | 内容 | 规格出处 | 后端消费方 | 前端消费方 |
| --- | --- | --- | --- | --- |
| `enums/story.ts` 等 | 全实体状态/类型枚举 + 中文 label 映射 | 02-业务流程规格 §4/§6/§7 各枚举表 | DTO 校验、Service 判断 | StatusTag、筛选器、动作条 |
| `permissions.ts` | 权限点常量 `PERMS = { story: { create: 'story.create', ... }, ... }` | 本文 §3/§4 权限点列 | `@Permissions()` 装饰器 + 种子扫描 | 菜单过滤/路由 meta/v-permission |
| `socket-contract.ts` | 事件名联合类型 + payload/ack TS 接口（card:move、ack 结构、eventId） | 本文 §6 Socket 契约 | Socket.IO 网关 | lib/socket.ts + useBoard |
| `kanban-map.ts` | 任务状态↔看板列映射（wait→wait/doing→developing/...） | 02 §8.1 | board 拖拽处理 | 拖拽语义提示 + WIP 角标 |
| `error-codes.ts` | 错误码枚举 + 默认中文文案 | 本文 §2 注册表 | BusinessException | lib/errors.ts 分发跳转 |
| `dto/` | API 入参出参 TS 类型（与 §5 DTO 字段一致；后端 class-validator DTO implements 之） | 本文 §5 + 04-数据字典 | DTO class 定义 | api/ 层函数签名 + zod schema |
| `filters.ts` | filter DSL 字段白名单注册表（module → 可筛选字段+op） | 本文 §7 | 列表查询解析校验 | lib/filters.ts 构造器 |

**规则**：

1. `packages/shared` **禁止依赖** nestjs/vue 任何运行时——只放常量与类型，保证双端零负担引用；
2. 改契约先改本文件对应章节 → 再改 shared → turbo 自动触发双端编译，**前端未适配即构建失败**；
3. 权限点种子脚本（§3.1）直接遍历 `PERMS` 常量生成 `sys_permission`——文档/常量/数据库三层同源；
4. 可选增强：CI 中由 Swagger 导出 `openapi.json` → `openapi-typescript` 校验 `dto/` 类型漂移（告警不阻塞，先跑通手工同步）。

> **落地进度（P0/F0 已交付）**：`error-codes.ts`（§2 完整注册表 + `httpStatusFor` 段位推导）、`dto/http.ts`（ApiResponse/PageResult/PageQuery）已落地并被双端消费；shared 为 ESM 单格式（`type: module`，nodenext 输出），`pnpm build` 已验证双端编译。
