## 1. 覆盖度总览（三口径，诚实量化）

| 口径 | 数值 | 说明 |
| --- | --- | --- |
| **核心研发管理闭环**（产品-项目-QA 铁三角主线） | **~85-90%** | 需求→计划→执行→版本→测试→Bug→发布全链可用，且逐条经禅道源码校准 |
| 功能模块口径 | **~28/102 ≈ 27%** | 禅道 102 模块中约 15 个为安装器/升级器/专版壳（不适用），实用模块约 60-70 个 |
| 功能点口径（实用模块内功能点） | **≈ 35-40%** | 禅道 20 年打磨的细节（批量操作/筛选器/导入导出/分支贯穿）是主要缺口 |

**结论**：核心主流程已可替代禅道日常使用；差距集中在 **DevOps 集成、BI 报表、自动化测试、企业系统管理** 四大板块与大量体验细节。策略=「核心已立住，按价值排序渐进补齐」。

## 4. 演进路线（三阶段）

### Phase A「前端驱动补口」（随 F2-F3 同步，1-2 个迭代）

> 原则：前端页面做到哪里，被暴露的接口缺口就在该迭代内补掉（禁止前端绕过造假数据）。

- **必做**：N01 多人任务、N02 Excel 导入导出、N03 自定义查询器、O01 邮件通道、K5 泳道卡片（O06）
- **顺带**：C01 分支贯穿、C03/C04 前端深化所需的小接口、R 组明细接口（bug 按日趋势）

### Phase B「高价值缺口」（前端主体完成后，1-2 个迭代）

- N04 webhook 投递器、N05/N06 DevOps 最小版（repo+GitLab）、N08 BI 一期、N09 备份、N10 日历+负载
- C 组批量消尾（C02/C05/C06/C07）

### Phase C「完善池」（按客户/需求拉取）

- N11-N16 + O 组长尾 + C 组 P2 项
- 准入规则：每项进入开发前须在本文档登记（编号/优先级/触发条件），完成时回填 docs/07 台账并同步 docs/08

## 5. 治理规则

1. 本文档是**缺口唯一登记处**：任何「禅道有而我们没有」或「有而不够好」的发现，先进 §2/§3 清单再排期；
2. 优先级定义：**P0**=主流程/前端阻塞，**P1**=高频价值，**P2**=低频/企业场景；
3. 每次迭代收口同步更新本档与 docs/08；推翻已登记判断时新增 ADR；
4. 与禅道新版本对齐：禅道大版本升级时重跑 §2 映射（增量 diff），保持基准新鲜。
