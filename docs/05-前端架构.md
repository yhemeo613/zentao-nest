| 决策点 | 选型 | 理由 |

| 路由 | vue-router 4（HTML5 mode） | |

## 2. 总体架构

```
┌────────────────────────────────────────────────────────────┐
│  浏览器 SPA（Vue3 + Vite 构建产物，nginx 容器托管）            │
│                                                            │
│  views/（页面，按业务域分模块）                                │
│    ↑ 复用                                                   │
│  components/（业务组件） + ui/（shadcn-vue 基础组件）           │
│    ↑                                                        │
│  composables/（useBoard/useAuth/usePermission/useUpload…）   │
│    ↑           ↑                                            │
│  stores/（Pinia：会话/权限/配置）  api/（模块化端点封装）        │
│    ↑                    ↑                                   │
│  router/（静态路由表+守卫）  lib/http（axios：解包/错误码/刷新） │
│                             ↑                               │
│                       lib/socket（看板实时）                  │
└──────────────┬─────────────────────────────┬───────────────┘
               │ HTTPS /api/v1/*             │ WebSocket /ws
     NestJS 后端（apps/server，01-总体设计）  Socket.IO 网关
               ↑ 共享契约：packages/shared（03 §12）
```

**数据流规则（单一数据源）**

1. 服务端状态（列表/详情）一律走 vue-query → key 约定 `['stories','list',filters]`；
2. 状态流转动作（start/finish/resolve…）= mutation → 成功后按后端返回影响面**精确失效**相关 query key（如任务 finish → 失效 `['tasks','detail',id]`、`['executions',execId,'tasks']`、`['stories',storyId]`、`['reports',…]`）；
3. 看板是唯一走「乐观更新 + Socket ack 回滚」的页面（§6）；
4. 会话/权限/偏好走 Pinia，不入 vue-query。

## 4. HTTP 层基础（lib/http.ts 规格）

| 职责 | 规格 |
| --- | --- |
| 基址 | `baseURL = import.meta.env.VITE_API_BASE`（默认 `/api/v1`）；dev 经 Vite proxy 转发避免 CORS |
| 请求头 | `Authorization: Bearer access_token`；`X-Trace-Id`（生成 uuid，响应回读透传到日志 toast） |
| **响应解包** | 拦截器解 `{code,message,data}`：`code===0` 返回 `data`；`code!==0` 抛 `ApiError(code,message,data)` |
| **错误码路由**（对齐接口清单 §2） | `2001/2002/2007` → 清会话跳 `/login?redirect=`；`2003` → 403 页（无功能权限）；`2004` → toast「无数据权限」；`3006` → toast「状态已变化」+ 触发当前列表 `invalidateQueries`；`1010` → toast 限流；其余 → 全局 message 展示 message |
| **401 并发刷新队列** | 收到 2002 且有 refresh_token → 单飞刷新（promise 队列挂起后续请求）→ 成功重放原请求；刷新失败 → 清会话去登录（不无限循环：刷新接口自身失败直接 reject） |
| 上传/下载 | 上传：multipart + 进度回调（useUpload）；下载：blob + 文件名从 Content-Disposition 解析 |
| 超时/重试 | 默认 15s；GET 幂等请求对网络错误自动重试 1 次 |

```ts
// lib/http.ts 核心骨架
const http = axios.create({ baseURL, timeout: 15_000 });
http.interceptors.request.use(attachTokenAndTraceId);
http.interceptors.response.use(
  (res) => res.data.code === 0 ? res.data.data : Promise.reject(new ApiError(res.data)),
  async (err) => { /* 401 刷新队列 → 重放；否则走 errors.ts 分发 */ }
);
```

## 5. 权限与路由基础

### 5.1 契约

- 登录后 `GET /auth/me` 返回：用户信息 + `permissions: string[]`（`module.action` 集合）+ 可见范围摘要 → 存入 Pinia（auth + permission store），并作为 vue-query 的根失效源（切用户时 `queryClient.clear()`）。
- **前端不做动态注册路由**：路由表静态声明，靠「菜单过滤 + 守卫 + 按钮级指令」三层收敛。理由：后端权限点=路由动作（module.action），页面粒度天然可静态声明；避免动态路由带来的刷新/收藏/缓存复杂度。

### 5.2 三层控制

| 层 | 机制 |
| --- | --- |
| 菜单层 | 侧栏菜单项声明 `permission`（如 `story.browse`），permission store 过滤后渲染 |
| 路由层 | `router.beforeEach`：① 无 token → `/login`（记录 redirect）；② `to.meta.permission` 存在且集合中无 → 403 页 |
| 按钮层 | `v-permission="'story.change'"`：无权限点直接移除元素（流转按钮/批量操作/管理入口） |

```ts
// directives/permission.ts 骨架
export const permission = {
  mounted(el, binding) {
    if (!usePermissionStore().has(binding.value)) el.remove();
  }
};
// meta 约定：{ permission: 'story.browse' | 'story.browse|story.view' }
```

### 5.3 受限组（limited）前端表现

后端已收敛数据与动作；前端只需同一套三层控制自动生效（limited 用户权限点集合更小），无需特判——**这是「权限点驱动 UI」的直接收益**。

## 6. 实时看板前端基础（对齐接口清单 §6 契约）

```ts
// lib/socket.ts 单例
io(VITE_WS_BASE, { auth: { token }, transports: ['websocket'], reconnectionDelayMax: 10_000 })
```

| 职责 | 规格 |
| --- | --- |
| 连接生命周期 | 登录后懒连接；token 刷新后 `disconnect→reconnect`（带新 token）；断线指数退避重连 + 重连成功后重放 `board:join` |
| 进板 | `board:join {executionId}` ack 返回全量 board → 写入 `['board', executionId]` query |
| **拖拽（乐观更新）** | 本地先移动卡片 → 发 `card:move`（带 eventId uuid）→ **ack ok**：以服务端返回 task/column 修正本地；**ack 失败**：按错误码回滚本地（恢复原列）+ toast（3006/4701 语义化文案）；服务端广播 `card:moved` 他人操作 → 直接更新缓存（比对 eventId 去重自己的回声） |
| 被动同步 | `card:status:changed / card:updated / column:updated / lane:updated` → patch 对应 query 缓存；`board:refresh` → `invalidateQueries(['board',executionId])` 全量拉取兜底 |
| WIP | `board:wip:exceeded` → 列头角标红色 +1（**不拦截**，与后端语义一致） |
| 在线成员 | `presence:sync` → 看板右上头像组；心跳由 socket 层自动（ping/pong） |

拖拽映射规则前端也要内置一份（与后端 taskColumnStatusList 同源）：拖到 `developed` 列即语义为 finish、拖回 `developing` 为 activate——**ack 失败文案按映射动作提示**（如「任务未开始，无法完成」）。

## 7. 通用页面范式（components/common + composables）

### 7.1 列表页模板（约占页面总数 70%）

```
PageHeader（标题+主操作按钮[v-permission]）
FilterBar（状态页签 + 筛选字段 + 自定义查询下拉 + 排序）
DataTable（@tanstack/vue-table：列显隐/固定列/行点击）
Pagination（page/pageSize/total 对齐后端 §1 约定）
```

### 7.2 详情页模板

左右布局：主栏（描述 Markdown 渲染 md-editor-v3 previewOnly + 动作按钮条=禅道动作全集）+ 右栏（字段面板：状态/指派/优先级/关联对象/操作日志 timeline=zt_action_log+history）。动作按钮条按 §5.1 权限点集合 + 实体当前状态渲染（isClickable 的前端镜像，双保险：后端仍校验）。

### 7.3 表单弹窗模板

vee-validate + zod（schema 与 api/types 的 DTO 同文件维护）；必填星标、提交 loading、`3001/3003` 字段级错误回填表单、`3004/3006/3007` 顶部告警。

### 7.4 筛选与自定义查询

`lib/filters.ts` 构造 `filters=field:op:value` 串（接口清单 §7 DSL 白名单在前端亦有字段注册表，双保险）；自定义查询 CRUD 走 `/queries`，下拉切换即改 vue-query key。

## 11. 构建与部署

- **构建**：`pnpm build` → 产物 `dist/`；chunk 策略：vendor（vue/echarts/socket）分包、路由级懒加载（全部 views 动态 import）。
- **环境变量**：`VITE_API_BASE`、`VITE_WS_BASE`、`VITE_SENTRY_DSN`（可选）。
- **部署**：多阶段 Dockerfile（node build → nginx:alpine 托管 dist）；nginx 配置：SPA history 回退、`/api` 反代后端、`/ws` WebSocket upgrade、静态资源 1 年强缓存（hash 文件名）、gzip/brotli。
- **集成**：monorepo 根 `docker-compose.yml` 四容器之一 `web`（见 [01-总体设计 §13](./01-总体设计.md)）；turbo 流水线串联：shared → server/web 并行 build → 双镜像 → compose up。
- **性能预算**：首屏 JS ≤ 500KB gzip、LCP < 2.5s、路由切换 chunk ≤ 200KB、长列表（>200 行）虚拟滚动。
