## 3. 阅读路径建议

- **只关心能不能做**：读 00 → 01 §1/§11（定位与计划）；
- **后端开发**：01 → 04（建实体）→ 03（写控制器）→ 02（实现流转时随查随对）；
- **前端开发**：05 → 03 §6/§13（Socket 与契约）→ 02（页面承载的业务规则）；
- **联调验收**：03 §13 契约对齐清单 + 02 的状态机逐条核对。

## 4. 修订规则

1. 每份文档头部维护版本与日期；实质变更递增小版本号；
2. 文档间冲突仲裁权见上表（例：任务状态流转以 02 为准，即使 01/03 简写与其不同）；
3. ADR 只增不改：推翻旧决策时新增一条并标注取代关系；
4. 编码期发现规格错误：先改 02/03/04，再同步代码——文档先行的原则不因赶工打破。
